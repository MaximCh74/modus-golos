## 1. Живой ИИ и телефон

владелец кладёт `OPENAI_API_KEY` в `.env` и делает `cloudflared tunnel login`.

### 1.1 Прогон LLM на живом ключе

Сейчас разбор совещания без ключа узнаёт только демо-планёрку. На защите могут попросить свою фразу, поэтому проверить:
1. Демо-планёрку из ТЗ §10.
2. Два-три **посторонних** текста, сочинить самим:
   - короткая планёрка про склад или поставки;
   - планёрка, где поручение звучит без имени («кто-нибудь посмотрите…»);
   - текст со смесью русского и казахского.

Править промпты, пока результат не станет стабильным. В `docs/STATUS.md` записать, что проверено на живом ключе.

### 1.2 Туннель и запись с телефона

- Если после `cloudflared tunnel login` зоны cq-systems.kz в списке нет, значит, домен не обслуживается Cloudflare. Сообщить владельцу и не выдумывать обход.

- Проверка с телефона:
  - QR-форма;
  - запись планёрки через MediaRecorder;
  - разбор;
  - отправка.
- Скрины с телефона — в отчёт.

## 2. Стиль «Модус Трейд»

Решение владельца: весь интерфейс в фирменном стиле заказчика — цвета, логотип, шрифты, элементы с modus-trade.kz. Свою палитру не придумываем.

### 2.1 Откуда брать

- **Точные значения** цветов, шрифтов, скруглений и отступов — из CSS их сайта modus-trade.kz, а не на глаз. Скрины сайта владелец прикладывает для ориентира.
- **Логотип** — с их сайта, лучше SVG. Используется только внутри демо для заказчика.
- **Шрифт.** Если он коммерческий, файлы шрифта в репозиторий не копируем. Берём ближайший бесплатный аналог (геометрический гротеск, например Montserrat или Manrope) и указываем это в `STATUS.md`.

### 2.2 Что видно на сайте (ориентир)

**Цвета:**
- тёмно-синий — заголовки, логотип, тёмные блоки;
- красный — акценты, кнопки, иконки, точки;
- белый фон;
- светло-серые рамки;
- серо-синий цвет для описательного текста.

**Логотип:** тёмно-синий круг с красной точкой и разрывом, надпись «МОДУС ТРЕЙД» жирным геометрическим шрифтом.

**Типографика:**
- заголовки — очень жирный геометрический гротеск, крупно, тёмно-синий;
- над заголовком красная метка-лейбл с короткой красной чертой слева («— Цифры», «— Почему мы»);
- основной текст светлый, серо-синий, с большим межстрочным интервалом.

**Кнопки:**
- основная — сплошная красная со скруглением, белый текст;
- вторичная — белая с красной обводкой, тёмный текст.

**Элементы:**
- вертикальный таймлайн: красные круги с белой иконкой-меткой, соединённые красной линией;
- декоративная сетка красных точек;
- круглые фото с красной дугой;
- диагональные тёмно-синие блоки.

**Тон:** деловой — «Ваш проектный партнер».

### 2.3 Как применить

- **Дизайн-токены** — CSS-переменные в одном месте; все экраны переводятся на них: QR-форма, страница статуса, `/app`, `/panel`.
- **Шапка:** их логотип + «Обратная связь». Подпись мелко на экране входа: «разработано Cyber QALQAN Systems».
- **Трекер статуса обращения** — в стиле их таймлайна: красные круги и красная линия для пройденных шагов, серые для будущих.
- **Маркеры карты** (этап 4) — их красная метка в круге.
- **Заголовки разделов** — с красным лейблом и чертой, как на сайте.
- **Кнопки** — их основная и вторичная.
- **Статусные цвета не путать с брендом.** Фирменный красный — для действий и акцентов. «Просрочено» и «отклонено» обозначаются отдельным приглушённым цветом и/или иконкой с подписью, чтобы обычная кнопка не читалась как тревога.
- **Декор** (сетка точек, дуги) — только на экране входа и в шапке QR-формы. Рабочие экраны остаются чистыми.
- **Проверка:** телефон 375 px и ноутбук. Скрины «до/после» в отчёт.

## 3. Остаток этапа 3 — ИИ в обращениях

ИИ-категория уже сделана в этапе 2. Осталось:

**Голосовой ввод:**
- в QR-форме — расшифровка прямо в поле текста;
- в приложении — расшифровка + черновик ИИ: суть, предлагаемое решение, тип, приоритет, уточняющий вопрос (ТЗ v1.1 §7).

**Похожие обращения:**
- эмбеддинги по открытым обращениям;
- при отправке — блок «Похоже, об этом уже сообщали»: [У меня так же] / [Всё равно отправить];
- в QR-форме — тот же блок, но коротко, максимум одно-два похожих.

**«Повторяющиеся темы»:**
- кластеры вместо «открытых по категориям» в сводке директора;
- подготовить данные для всплывашки карты (этап 4).

**Без ключа:**
- похожие обращения — по ключевым словам;
- на экране честная пометка, как в этапе 2.

**Тесты:** голос → поле; похожее находится; «У меня так же» не создаёт дубль; кластеры считаются.
