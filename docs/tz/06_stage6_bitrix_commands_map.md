## 1. Битрикс24 по-настоящему

**Действие владельца:** регистрирует тестовый облачный портал Битрикс24 (пробный период нового портала) и, если понадобится, включает демо-режим подписки в «Мой тариф».

**Сессия:**
- даёт владельцу короткие пошаговые инструкции;
- сама ничего не регистрирует и не оплачивает.

### 1.1 Что сделать на тестовом портале

1. **Локальное приложение** в портале: наша система открывается внутри Битрикса, пункт в левом меню.
2. **Вход через Битрикс24 (OAuth 2.0):**
   - внутри портала пользователь опознаётся автоматически;
   - снаружи — кнопка «Войти через Битрикс24» на нашем сайте;
   - сопоставление с нашими пользователями — по ID или почте Битрикса;
   - на портале завести тестовых сотрудников под демо-имена (Виктор, Олег, Ерлан, Айгерим, Сауле…);
   - «Войти как…» оставить как запасной демо-вход.
3. **Уведомления в чат Битрикса.** Все наши уведомления дублируются в мессенджер Битрикс24 со ссылкой обратно на обращение. Уведомления на сайте остаются.
4. **По желанию, если идёт без проблем:** поручения с совещаний → задачи Битрикс24 со ссылкой обратно.

Методы REST и скоупы — по актуальной документации Битрикс24, сверить перед реализацией. Обновить `docs/BITRIX24.md`, отметить, что проверено на живом портале.

**Без тестового портала** всё остаётся планом в `docs/BITRIX24.md`. Ничего не имитировать под видом работающей интеграции.

## 2. Команды директора голосом или текстом («Джарвис»)

### 2.1 Где

На главной директора (в панели и в приложении) — кнопка с микрофоном «Команда» и поле для текста (запасной путь, если микрофон не работает).

### 2.2 Как работает

1. Голос → STT → LLM разбирает команду в строгий JSON: `{intent, filters, deadline, note}`.
2. Допустимы только команды из белого списка:

| intent | Что делает |
|---|---|
| `remind_overdue_tasks` | напомнить исполнителям просроченных поручений с совещаний |
| `request_progress` | попросить ответственных «Сообщить о ходе» по обращениям «В работе» (все или без новостей дольше порога) |
| `remind_no_response` | напомнить ответственным об обращениях без первого ответа или просроченных по SLA |
| `open_decision` | открыть «На решение» с выбранной идеей («прими идею про шаблон КП»); решение директор принимает сам кнопкой |
| `read_briefing` | прочитать сводку |

   Фильтры: все / город / подразделение / конкретный человек. Срок: «сегодня», «до пятницы», «до 18:00».
3. Сервер сам считает получателей и обращения. ИИ получателей не выбирает.
4. **Экран подтверждения** — всегда, без исключений:
   - «Отправить напоминание 4 сотрудникам по 5 обращениям»;
   - список «кто — что»;
   - текст сообщения;
   - кнопки [Отправить] / [Изменить] / [Отмена].
5. **Текст сообщения всегда нейтральный и вежливый**, независимо от того, как сформулирована команда. Пример: «Виктор просит сегодня до 18:00 сообщить о ходе работ по A-007».
6. **После отправки:**
   - уведомления получателям (на сайте и в Битрикс24, если подключён);
   - событие в истории каждого обращения: «Директор запросил новости»;
   - короткий голосовой ответ: «Отправил напоминания четырём сотрудникам».
7. **Не понял команду** — ответ «Не понял команду. Могу: …» со списком команд.

### 2.3 Запрещено

- любые действия без подтверждения;
- команды вне белого списка;
- ИИ сам принимает или отклоняет идеи.

### 2.4 Без ключа

Распознавание команд по ключевым словам для тех же пяти команд, с той же обязательной страницей подтверждения.

### 2.5 Тесты

- резкая формулировка → вежливый текст;
- фильтр по городу;
- без подтверждения ничего не уходит;
- неизвестная команда → список возможностей.

## 3. Главная страница: карта вместо стены QR

Стартовая страница — интерактивная карта.

**Рамка:**
- карта обрезана по региону городов: полоса Самара — Тюмень — Омск — Астана — Павлодар, с небольшим запасом;
- контуры России и Казахстана внутри рамки — тонко и спокойно;
- страны целиком не рисуем: города крупнее, нет спорных границ.

**Точки:**
- Омск (головной офис), Самара, Тюмень, Астана, Павлодар (подпись «производство») — фирменные красные метки;
- слой «Объекты» — маленькие серые точки.

**Нажатие на город — карточка:**
- название и тип подразделения;
- открытых и решённых за месяц;
- главная тема;
- QR этого города;
- кнопка «Подать обращение» (ведёт в QR-форму филиала).

**Шапка:** логотип, одна строка «Есть идея или проблема? Выберите город или отсканируйте QR», кнопка «Войти» (Битрикс24, если подключён, и демо-вход).

**Телефон:** карта сверху, ниже список городов кнопками.

Использовать **тот же компонент карты**, что у директора. Стена QR со стартовой убирается: QR остаются в карточках городов и на плакатах.

## 4. Правила для фронта — уже сейчас

- **Никаких эмодзи** в интерфейсе. Заменить существующие.
- **Один набор линейных SVG-иконок** с открытой лицензией (например, Lucide или Tabler), встроенных в страницу. Цвет — тёмно-синий или серый.
- **Палитра:** тёмно-синий, красный, белый, два серых + приглушённые статусные цвета. Красный — только для основных действий и фирменных акцентов.
- Новых цветов и декоративных элементов не добавлять.
- **Финальная чистка интерфейса** (упрощение экранов, удаление лишнего) — отдельным этапом после функционала, по отдельному ТЗ. владелец может принести референсы экранов.
