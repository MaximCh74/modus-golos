# Битрикс24: как встроить обратную связь в портал заказчика

По первому интервью сотрудники не будут ставить отдельное приложение — удобнее всего Битрикс24. Ниже: что сделать владельцу,
чтобы получить тестовый портал; что проверено по официальной документации (apidocs.bitrix24.ru, сверено 12.11.2026); как
устроена интеграция в коде и что из этого проверено на живом портале.

## Статус (честно)

| Часть | Состояние на 12.11.2026 |
|---|---|
| Инструкция по тестовому порталу и демо-режиму подписки | готова (ниже) — выполняет владелец, сессия ничего не регистрирует и не оплачивает |
| Методы и скоупы | сверены по apidocs.bitrix24.ru (ссылки в тексте) |
| Код интеграции (`mf/integrations/bitrix.py`, маршруты `/bitrix/*` в `mf/main.py`) | написан по документации, покрыт тестами с подменённым HTTP (`tests/test_stage6.py`); **на живом портале не проверен** — ждёт тестовый портал |
| Без настроек в `.env` | интеграция выключена: кнопок «Войти через Битрикс24» нет, уведомления не дублируются, `/bitrix/*` отвечает 404. Ничего не имитируется |
| Проверено на живом портале | **пока ничего** — портала нет. После проверки здесь появятся скрины: пункт в левом меню, вход, уведомление в чате |

## 1. Что сделать владельцу: тестовый портал (10–15 минут)

1. **Создать портал**: https://www.bitrix24.kz/create/ (для .ru — https://www.bitrix24.ru/create/) → «Создать бесплатно» → почта
   (лучше корпоративная) → имя портала, например `modus-test.bitrix24.kz`. Новый облачный портал получает **15 дней тарифа
   «Профессиональный» бесплатно** (справка Битрикс24: «демо — доступ на 15 дней к возможностям тарифа Профессиональный»).
2. **Включить демо-режим подписки**: в верхнем меню виджет **«Мой тариф»** → раздел **«BitrixGPT + Маркетплейс»** → **«Включить демо»**
   ([доступ к REST API](https://apidocs.bitrix24.ru/first-steps/access-to-rest-api.html)). Без этого на бесплатном тарифе REST API и
   локальные приложения недоступны ([возможности бесплатного тарифа](https://helpdesk.bitrix24.ru/open/28721100/)). Признак, что всё
   включилось: в левом меню появился пункт **«Разработчикам»**.
3. **Завести тестовых сотрудников под демо-имена** («Сотрудники» → «Пригласить» или «Добавить сотрудника»): Виктор Орлов (директор),
   Олег Савельев, Ерлан Жумабеков, Айгерим Нурланова, Сауле Абишева, Гульнара Сейтжанова. Почта любая (можно псевдонимы одной почты):
   система сопоставляет сотрудников по ID Битрикса, по почте или по имени и фамилии — для демо-имён сработает имя.
4. **Создать локальное приложение**: «Разработчикам» → вкладка «Готовые сценарии» → «Другое» → **«Локальное приложение»**
   ([локальные приложения](https://apidocs.bitrix24.ru/local-integrations/local-apps.html)):
   - тип — **серверное**, галочка «с интерфейсом» (приложение показывает нашу страницу внутри портала);
   - **Путь обработчика**: `https://modus.cq-systems.kz/bitrix/app`;
   - **Путь для первоначальной установки**: `https://modus.cq-systems.kz/bitrix/install`;
   - **Название пункта меню**: `Модус Голос` — пункт появится в левом меню;
   - **Права (скоупы)**: `user` («Пользователи» — кто вошёл, его почта и должность), `im` («Чат и уведомления» — дубль уведомлений),
     `task` («Задачи» — поручения с совещаний → задачи, по желанию). Лишних прав не просить.
   - Сохранить → портал покажет **код приложения (client_id)** и **ключ (client_secret)** — ключ показывается один раз, скопировать сразу.
5. **Положить секреты в `.env`** на ноутбуке с системой (файл в `.gitignore`, в чат не писать):

   ```
   BITRIX_PORTAL=modus-test.bitrix24.kz
   BITRIX_CLIENT_ID=local.xxxxxxxx.xxxxxxxx
   BITRIX_CLIENT_SECRET=…
   BITRIX_TASKS=1        # по желанию: поручения → задачи Битрикса
   ```

   Перезапустить сервер (`preview_start modus-dev` или uvicorn). Проверка: `curl -s https://modus.cq-systems.kz/api/public/config` → `"bitrix": true`.
6. **Установить приложение**: в карточке приложения нажать «Установить» (или открыть пункт «Модус Голос» в левом меню). Битрикс
   вызовет `/bitrix/install`, система сохранит токены портала (`var/bitrix_tokens.json`, не в git) и ответит страницей, которая
   вызывает `BX24.installFinish()` — без этого приложение остаётся «в установке»
   ([завершение установки](https://apidocs.bitrix24.ru/settings/app-installation/installation-finish.html)).
7. **Проверить три вещи и сделать скрины** (п. 5 ТЗ): пункт «Модус Голос» в левом меню открывает систему и сотрудник опознан
   без «Войти как…»; на `https://modus.cq-systems.kz/login` есть кнопка «Войти через Битрикс24» и она работает; при смене статуса
   обращения у сотрудника в чате Битрикса появляется уведомление со ссылкой обратно.

**Быстрый путь только для уведомлений (без приложения):** «Разработчикам» → «Другое» → «Входящий вебхук» со скоупом `im` →
адрес вебхука в `.env` как `BITRIX_WEBHOOK_URL=https://modus-test.bitrix24.kz/rest/1/xxxxxxxx/` (секрет никому не передавать).
Тогда дубли уведомлений работают, а вход через Битрикс24 — нет (для него нужно приложение).

## 2. Что проверено по документации (12.11.2026)

- **Вход, OAuth 2.0** ([полный протокол](https://apidocs.bitrix24.ru/settings/oauth/index.html)): пользователь отправляется на
  `https://<портал>/oauth/authorize/?client_id=…&state=…` (адрес возврата Битрикс берёт из настроек приложения — для локального
  приложения это «Путь обработчика»); обратно приходят `code` (живёт 30 с), `state`, `domain`, `member_id`, `scope`. Сервер меняет код
  на токены: `GET https://oauth.bitrix24.tech/oauth/token/?grant_type=authorization_code&client_id=…&client_secret=…&code=…` →
  `access_token` (1 час), `refresh_token` (180 дней), `client_endpoint` (`https://<портал>/rest/`), `member_id`, `scope`, `status`.
  Обновление — тот же адрес с `grant_type=refresh_token` ([автообновление](https://apidocs.bitrix24.ru/settings/oauth/auto-renewal.html));
  на истёкший токен REST отвечает `expired_token` (401). `client_secret` только на сервере.
- **Внутри портала** ([упрощённый способ](https://apidocs.bitrix24.ru/settings/oauth/simple-way.html)): приложение «с интерфейсом»
  открывается в iframe, и Битрикс каждый раз POST-ом передаёт `AUTH_ID` (= access_token), `AUTH_EXPIRES`, `REFRESH_ID`, `member_id`,
  `APPLICATION_TOKEN`, `APPLICATION_SCOPE`, `status`, `PLACEMENT`; в query — `DOMAIN`, `PROTOCOL`, `LANG`, `APP_SID`. Пользователь
  опознаётся автоматически: `user.current` с этим токеном.
- **REST-вызов**: `{client_endpoint}{метод}?auth=<access_token>`; ответ `{"result": …}` или `{"error": …, "error_description": …}`.
- **Кто вошёл** — [`user.current`](https://apidocs.bitrix24.ru/api-reference/user/user-current.html) (скоуп `user`, `user_brief` или
  `user_basic`): `ID`, `NAME`, `LAST_NAME`, `EMAIL`, `WORK_POSITION`, `UF_DEPARTMENT`, `PERSONAL_PHOTO`, `ACTIVE`. Список —
  [`user.get`](https://apidocs.bitrix24.ru/api-reference/user/user-get.html) (фильтр по `EMAIL` в документации не подтверждён — поэтому
  сопоставляем по тому, что вернул `user.current`).
- **Уведомление в чат** — [`im.notify.system.add`](https://apidocs.bitrix24.ru/api-reference/chats/notifications/im-notify-system-add.html)
  (скоуп `im`): `USER_ID`, `MESSAGE` (BB-коды, в т. ч. `[URL=…]…[/URL]` — так даём ссылку обратно на обращение), `MESSAGE_OUT`, `TAG`,
  `SUB_TAG`, `ATTACH`; → id уведомления; нельзя вызывать сессионной авторизацией — только токен приложения или вебхук. Есть парный
  [`im.notify.personal.add`](https://apidocs.bitrix24.ru/api-reference/chats/notifications/im-notify-personal-add.html) (от имени текущего
  пользователя); берём системное — оно от имени приложения «Модус Голос».
- **Поручение → задача** — [`tasks.task.add`](https://apidocs.bitrix24.ru/api-reference/tasks/tasks-task-add.html) (скоуп `task`, не
  устаревший `tasks`): `fields: {TITLE, RESPONSIBLE_ID, DESCRIPTION, DEADLINE в ISO 8601 «2026-11-14T18:00:00»}` → `result.task.id`.
- **Скоупы** ([список](https://apidocs.bitrix24.ru/api-reference/scopes/permissions.html)): `user` (версии `user_brief`, `user_basic`),
  `im`, `imbot` (боты — не нужен), `task`, `placement` (виджеты — не нужен: пункт меню задаётся в форме приложения).
- **Тарифы**: бесплатный тариф без REST и приложений; платный + подписка «BitrixGPT + Маркетплейс» или демо-режим подписки
  ([доступ к REST API](https://apidocs.bitrix24.ru/first-steps/access-to-rest-api.html)). У заказчика по его ответу облачный портал с
  подпиской на Маркетплейс. Перед пилотом сверить тариф в «Мой тариф».

## 3. Как это устроено в коде

- `mf/integrations/bitrix.py` — настройки из `.env` (`BITRIX_PORTAL`, `BITRIX_CLIENT_ID`, `BITRIX_CLIENT_SECRET`, `BITRIX_WEBHOOK_URL`,
  `BITRIX_TASKS`), обмен кода на токены и обновление, REST-вызов с повтором после `expired_token`, сопоставление сотрудника
  (`users.bitrix_id` → `users.email` → имя и фамилия; найденное запоминается), дубль уведомления `im.notify.system.add` в фоне,
  `tasks.task.add` при отправке совещания (если `BITRIX_TASKS=1`). Токены портала — `var/bitrix_tokens.json` (папка данных, не база:
  база уходит в демо-снапшот в git).
- Маршруты (`mf/main.py`): `GET /bitrix/login` → авторизация на портале; `GET /bitrix/callback` и `GET /bitrix/app?code=…` → токены →
  `user.current` → сессия; `POST /bitrix/app` (iframe, `AUTH_ID`) → сессия с cookie `SameSite=None; Secure` (иначе браузер не отдаёт
  cookie внутри чужого сайта); `POST /bitrix/install` → токены портала + страница с `BX24.installFinish()` (на этом маршруте CSP
  разрешает `https://api.bitrix24.com`). С настроенной интеграцией CSP получает `frame-ancestors https://*.bitrix24.kz …` вместо
  `'none'`, `X-Frame-Options` снимается.
- Фронт: `/login` и стартовая показывают «Войти через Битрикс24», только если `/api/public/config` вернул `bitrix: true`; «Войти как…»
  остаётся запасным демо-входом. Администратор видит статус интеграции и может вписать почту / ID Битрикса сотруднику
  (Панель → Администрирование → Сотрудники).
- Уведомления на сайте остаются; дубль в Битрикс уходит из того же `appeals.notify`, что и внутренние уведомления, — значит, все
  уведомления системы (статусы, уточнения, «обсудили на совещании», поручения, команды директора) дублируются одинаково.

## 4. Что даёт интеграция (по убыванию ценности)

1. Страница системы внутри портала — пункт «Модус Голос» в левом меню, вход без паролей.
2. Уведомления в мессенджер Битрикса со ссылкой обратно — сотруднику не нужно заходить в систему, чтобы узнать о статусе.
3. Поручения с совещаний → задачи Битрикса (по желанию), обратная синхронизация статуса — следующий шаг (`ONTASKUPDATE`).
4. Сотрудники и подразделения из портала (`user.get`, `department.get`) вместо ручного seed — после пилота.
5. Чат-бот «Модус Голос» (`imbot.register`) — отдельно, если понадобится.

## Roadmap

Интеграция с Битрикс24 — первая в дорожной карте: по кастдеву сотрудники работают в Битриксе и не ставят отдельных приложений,
а поручения с совещаний сегодня разбросаны по 1С, Битриксу и Excel. Следующий шаг после неё — 1С: справочник номенклатуры как
источник для категории «Номенклатура и спецификации» (главная повторяющаяся тема).
