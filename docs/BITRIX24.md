# Битрикс24: как встроить обратную связь в портал заказчика

По первому интервью сотрудники не будут ставить отдельное приложение — удобнее всего Битрикс24. Ниже — что проверено по
официальной документации (11.11.2026), что возможно на каком тарифе и пошаговый план установки для администратора портала.
Это **план интеграции**: в демо показывается честно как план, код интеграции в MVP не входит.

## Что возможно на каком тарифе (проверено по справке Битрикс24)

- **Бесплатный тариф**: вебхуки, локальные приложения и REST API недоступны — так с 2021 года
  ([как изменился бесплатный тариф](https://www.bitrix24.com/about/blogs/bitrix24-tips-and-updates/how-a-free-bitrix24-plan-is-going-to-change-after-january-1-2021.php),
  [возможности бесплатного тарифа](https://helpdesk.bitrix24.ru/open/28721100/)).
- **Платные тарифы + подписка «BitrixGPT + Маркетплейс»**: REST API, вебхуки, локальные приложения и приложения из каталога.
  Путь: «Мой тариф» → «Подписка на BitrixGPT + Маркетплейс» → «Купить подписку»; на бесплатном тарифе сначала нужно перейти
  на платный ([доступ к REST API](https://apidocs.bitrix24.ru/first-steps/access-to-rest-api.html),
  [новые условия подписки с 20.11.2024](https://helpdesk.bitrix24.ru/open/23776074/)).
  **У заказчика по его ответу облачный портал с подпиской на Маркетплейс — значит, всё необходимое уже есть.**
- **Пробный режим**: в «Мой тариф» → раздел BitrixGPT + Маркетплейс → «Включить демо» — REST API и локальные приложения на
  время демо; отдельно новый портал получает 15-дневный пробный период старшего тарифа
  ([справка](https://helpdesk.bitrix24.com/open/12357038/)). Для зоны .kz и .ru условия те же.
- **Важно по срокам**: Битрикс24 меняет линейку тарифов; по справке с 30.11.2026 на младшем тарифе REST API отключается —
  перед пилотом сверить тариф заказчика в «Мой тариф».
- **Тестовый портал для демо**: завести бесплатный облачный портал и включить демо-режим Маркетплейса может только
  владелец учётной записи; регистрация портала и платные подписки — действие заказчика или команды, не автоматизации.
  Если пробного режима не хватит, потребуется платный тариф — сообщаем, сами не оформляем.

## Что даёт интеграция (по убыванию ценности)

1. **Страница системы внутри портала** — наша форма и «Мои обращения» в левом меню Битрикса. Минимум — ссылка в меню
   (без REST); полноценно — локальное приложение с iframe-страницей.
2. **Уведомления в мессенджер Битрикса** о смене статуса, уточнении, итоге, «обсудили на совещании» — метод `im.notify.system.add`
   через входящий вебхук или приложение со скоупом `im`.
3. **Чат-бот «Обратная связь»** — обращение можно отправить сообщением боту (`imbot.register`, события `ONIMBOTMESSAGEADD`),
   бот отвечает номером и ссылкой на статус.
4. **Поручения с совещаний → задачи Битрикса** (`tasks.task.add` со ссылкой обратно на совещание; срок и исполнитель из
   разбора), статус выполнения — обратно по событию `ONTASKUPDATE`.
5. **Сотрудники из портала** — `user.get` для списка и подразделений вместо ручного seed; вход через OAuth приложения.

## Пошагово для администратора портала (локальное приложение)

Источник: [создание вебхуков и приложений](https://helpdesk.bitrix24.ru/open/20886106/),
[локальные приложения](https://apidocs.bitrix24.ru/local-integrations/local-apps.html).

1. Убедиться, что на портале активна подписка BitrixGPT + Маркетплейс (или включён демо-режим).
2. «Разработчикам» → вкладка «Готовые сценарии» → «Другое» → «Локальное приложение». Создавать приложения «для всех» может
   только администратор портала; права настраиваются в «Безопасность».
3. Тип — серверное приложение с интерфейсом. Указать:
   - «Путь обработчика»: `https://modus.cq-systems.kz/bitrix/install` (адрес нашей системы; для пилота — сервер заказчика);
   - «Путь для первоначальной установки»: тот же адрес с `/bitrix/install`;
   - пункт меню: «Обратная связь» (страница откроется внутри портала в iframe).
4. Права (скоупы): `user` (сотрудники и подразделения), `im` (уведомления и чат-бот), `imbot` (бот), `task` (поручения → задачи),
   `placement` (пункт меню и встраивание). Лишних прав не запрашивать.
5. Сохранить — портал выдаст `client_id` и `client_secret`; они кладутся в `.env` нашей системы (`BITRIX_CLIENT_ID`,
   `BITRIX_CLIENT_SECRET`), в репозиторий не попадают.
6. Нажать «Установить» — Битрикс вызовет путь установки, система сохранит токены портала и пропишет пункт меню.
7. Для быстрого старта без приложения: «Готовые сценарии» → входящий вебхук со скоупом `im` → URL вебхука в `.env`
   (`BITRIX_WEBHOOK_URL`) — этого достаточно для уведомлений о статусах. Секрет вебхука никому не передавать.

## Что менять в нашей системе для пилота

- Модуль `mf/integrations/bitrix.py`: установка приложения (OAuth-токены портала), `im.notify.system.add` на уведомлениях
  (там же, где сейчас in-app и SSE — `appeals.notify`), `tasks.task.add` при отправке совещания, синхронизация статуса задач.
- Встраивание страницы: в iframe Битрикса нужен `frame-ancestors https://*.bitrix24.kz https://*.bitrix24.ru` в CSP
  (сейчас `'none'`), вход — по идентификатору пользователя портала вместо демо-входа.
- Чат-бот и задачи — после страницы и уведомлений, если идут без проблем.

## Roadmap

Интеграция с Битрикс24 — первая в дорожной карте: по кастдеву сотрудники работают в Битриксе и не ставят отдельных
приложений, а поручения с совещаний сегодня разбросаны по 1С, Битриксу и Excel. Следующий шаг после неё — 1С:
справочник номенклатуры как источник для категории «Номенклатура и спецификации» (главная повторяющаяся тема).
