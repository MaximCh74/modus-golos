# Демо «Модус Голос» на защите: предсказуемо, с запасным ходом на каждом шаге

Цель — показать шесть болей собственника и как их закрывает система. Три устройства, живой ИИ, на каждом шаге запасной ход.
Формат (длительность, Wi-Fi, проектор) уточняется у организаторов; сценарий сокращается до четырёх шагов (§5).

## 1. Устройства и роли

| Устройство | Кто в системе | Что показывает |
|---|---|---|
| **Ноутбук** (проектор) | Сергей Михайлович — директор | `/panel#/summary`: ИИ-сводка, карта, повторяющиеся темы; «На решение»; очередь |
| **Телефон ведущего** | Олег Савельев — руководитель | `/app#/meeting`: запись планёрки, разбор, отправка; «Мои поручения» |
| **Телефон жюри** | без входа | QR-плакат → `/q/PVL`: голосом → обращение → статус по ссылке |

Адрес — постоянный: **https://modus.cq-systems.kz** (туннель с ноутбука, сервер и GPU на нём). Демо-вход без паролей: `/login`.
QR-плакаты — `demo/qr_posters.pdf`, большой QR для слайда — `demo/slides/qr_slide_PVL.png`.

## 2. За час до выхода

```bash
tools/preflight.sh          # сервер, туннель снаружи, ключ, STT на GPU, база в демо-состоянии, диск, батарея
tools/demo_reset.sh         # вернуть базу в демо-состояние (секунды, без ИИ); даты сдвигаются на «сегодня»
tools/preflight.sh --no-key # запасной режим без ключа проходит сценарий на заскриптованных разборах
```

После `demo_reset.sh` сессии сброшены — войти заново на всех устройствах. На ноутбуке открыть `/panel#/summary`,
на телефоне ведущего `/app#/meeting`. Телефон жюри — ничего заранее, только плакат. Для шага 1б распечатать карточку Нурлана
(«Администрирование» → «Сотрудники» → строка Нурлана Серикбаева → «Карточка PDF») — после сброса базы ссылка свежая.

## 3. Сценарий по болям собственника

### Шаг 1 — «Вопросы приходят хаотично» (QR + голос)
- **Жюри, телефон**: навести камеру на плакат «Павлодар» → «Проблема» → кнопка микрофона → сказать 15–20 секунд (например: «на складе
  сканер штрихкодов не читает этикетки номенклатуры из 1С, артикулы вбиваем вручную, прошу заменить») → остановить → под полем «Мы поняли так: …» →
  чип «Прямо сейчас мешает» → «Отправить». Если появился блок «Похоже, об этом уже сообщали» (похожие обращения о
  номенклатуре в 1С) — это тоже демонстрация: сказать «система видит повтор» и нажать «Всё равно отправить» → номер и ссылка на статус.
- **Ожидаемо на проекторе**: маркер Павлодара мигает, в очереди обращение с «Коротко», категорией «Номенклатура и спецификации»
  или «1С и автоматизация», ответственным и приоритетом «высокий».
- **Запасной ход**: микрофон не дал разрешение → напечатать текст вручную; нет связи у жюри → ведущий открывает `/q/PVL` со
  своего телефона; совсем нет связи → показать скрин `demo/slides/01_qr_voice.png` и перейти к шагу 2.

### Шаг 1б — вариант: «У рабочих нет Битрикса» (сотрудник без аккаунта за минуту)
- **Ноутбук, администратор** (`/login` → Игорь Лебедев → «Администрирование» → раздел «Сотрудники» вверху): «Добавить» →
  имя, город **Павлодар**, отдел **Производство**, должность, телефон → «Добавить» (галочка «сразу выдать личное приглашение» стоит) →
  открывается карточка сотрудника: QR, ссылка, «Отправить в WhatsApp», «Скопировать приглашение», «Карточка PDF». Сказать: «рабочих и командированных нет в Битриксе — им не нужны ни
  пароли, ни установка: администратор печатает карточку, человек один раз открывает её камерой».
- **Телефон жюри или ведущего**: навести камеру на QR с экрана (или на напечатанную карточку) → «Здравствуйте, …!» → **«Войти»** →
  приложение рабочего: «Мои баллы: 0», кнопки «Сообщить о проблеме» / «Предложить улучшение». Открыть ссылку второй раз с другого
  телефона — «Ссылка уже использована»: вход одноразовый, устройство помнит сотрудника.
- Если спросят про списки: «Импорт из CSV или Excel» → шаблон → ошибочная строка попадает в отчёт, остальные заводятся, карточки
  печатаются пачкой на весь импорт; если человек появится и в Битриксе — профили склеятся по телефону или почте.
- **Запасной ход**: карточка напечатана заранее для рабочего из демо-данных — **Нурлан Серикбаев, Павлодар — производство**
  (приглашение действует 14 дней от сброса базы; после `demo_reset.sh` ссылка снова свежая — распечатать из «Сотрудники» → строка Нурлана →
  «Карточка PDF»). Совсем нет связи у телефона — показать скрины `docs/screens/stage8/45…47`.

### Шаг 2 — «Совещания приходится вспоминать» (планёрка)
- **Живьём, ведущий, телефон**: `/app#/meeting` → «Начать запись» → короткая запись 30–40 секунд (две-три реплики: «Ерлан, до
  пятницы собери список операций с повторным вводом», «Айгерим, подготовь правило для отдела», «идея — шаблон КП, отправим
  директору») → «Завершить» → «Расшифровываем… → Разбираем…» (10–20 с) → экран разбора.
- **Полная планёрка** (2–3 минуты на 2–3 голоса по §10) — не живьём, а «Загрузить аудио или видеозвонок» с телефона: файл
  лежит на телефоне заранее; либо показать уже разобранную в `/panel#/meetings`.
- Показать флаг «нет срока» у Айгерим → поставить дату → «Отправить».
- **Ожидаемо на проекторе**: у директора в «На решение» прилетела идея про шаблон КП (SSE, без обновления); у Павла — «A-007
  обсудили на совещании».
- **Запасной ход**: запись не пошла → «Загрузить аудио или видеозвонок» (файл заранее на телефоне) или «Вставить текст
  расшифровки» → «Подставить демо-планёрку из ТЗ §10»; ИИ не ответил → плашка «Демо-разбор без ИИ», пункты те же; показать уже
  разобранную «Планёрку 11.11» в `/panel#/meetings`.

### Шаг 3 — «Сотрудник думает, что решается, а забыли»
- **Ноутбук**: открыть обращение жюри в очереди (вкладка «Требуют внимания» — оно там, пока без ответственного или «мешает сейчас») → **«Взять в работу»** →
  **«Сообщить о ходе»**: «Сканер заказан, поставка в среду» → «Отправить автору» → на телефоне жюри по ссылке статуса видно стадию
  «Проработка» и новость; в меню «…» карточки — «Уточнить у автора: вопрос ИИ», если «суть неясна».
- Показать «Требуют внимания» на сводке («без новостей N») или колонку «Новость автору» (кнопка «Вид» в очереди) и уведомление
  «Автор ждёт новостей по A-003» у Анны (`/login` → Анна → значок уведомлений).
- **Запасной ход**: нет связи у жюри → показать `/t/<ссылка>` с ноутбука во второй вкладке.

### Шаг 4 — «Нужно видеть, что требует решения»
- **Ноутбук**: `/panel#/summary` → сводка: «Добрый день, Сергей Михайлович…» → «Озвучить» (OpenAI TTS тем же ключом, кэш на сервере;
  без ключа — голос браузера, если есть русский) → строка «Требуют внимания: … ждут решения 2 · мешают работать N» → `На решение`
  → A-027 «ждёт 12 дн» → «Принять» с комментарием; идея с планёрки → «Принять» → обращение уходит руководителю продаж.
- **Команда директора** (блок «Команда» под сводкой, голосом в микрофон или текстом): **«Пусть Омск до шести вечера расскажет,
  что по обращениям в работе»** → экран подтверждения: «Отправить запрос новостей одному сотруднику по одному обращению», Олег —
  A-015, текст «Сергей Михайлович просит сегодня до 18:00 сообщить о ходе работ по обращению A-015» → «Отправить» → у Олега уведомление,
  в истории A-015 «Директор запросил новости», короткий голосовой ответ. В зале собственник и сотрудники — формулировка только такая,
  без грубостей. Без ключа та же фраза разбирается по ключевым словам.
- **Запасной ход**: сводка пришла шаблоном (плашка «шаблон без ИИ») — говорим то же самое, числа те же; озвучка не
  заиграла — читаем вслух. Перед выходом нажать «Озвучить» один раз: mp3 ляжет в кэш. Команда не разобралась — напечатать её
  текстом в то же поле.

### Шаг 5 — «Команда перестанет предлагать»
- **Ноутбук или телефон**: `/app#/changes` → «Спасибо» под внедрённой идеей → профиль автора (`/app#/u/6`, Сауле: аватарка,
  баллы, внедрено, «спасибо») → `/app#/league` → `/app#/rewards` → «Премия за внедрённую идею» → `/rules`.
- **Запасной ход**: показать скрины `demo/slides/05_*.png`.

### Шаг 6 — Финал
- **Ноутбук**: карта — пять городов и объект в Атырау; «Повторяющиеся темы» — «Номенклатура в 1С»: 5 обращений из 5 городов;
  путь в Битрикс24 — `docs/BITRIX24.md` (страница в портале, уведомления, поручения → задачи).

## 4. Если что-то пошло не так

- **Wi-Fi площадки не работает** — раздача с телефона: включить точку доступа на телефоне → ноутбук к ней → туннель поднимется
  сам (`systemctl --user status cloudflared-modus`; если нет — `systemctl --user restart cloudflared-modus`) → `tools/preflight.sh`.
  Телефоны жюри и ведущего ходят на адрес через интернет, а не в локальную сеть, поэтому им нужен любой интернет.
- **Интернета нет совсем** — локально: ноутбук `http://localhost:8070`, QR не работает → ведущий показывает всё с ноутбука; ИИ
  недоступен → запасной режим (демо-разбор, словарь, шаблон сводки) включается сам, всё помечено честно.
- **Сервер упал** — `preview_start modus-dev` или `python3 -m uvicorn mf.main:app --port 8070`; база не теряется.
- **Живое демо невозможно** — видеозапись прогона `demo/backup.mp4` и скрины `demo/slides/`.
- **Ключ OpenAI не работает** — `tools/preflight.sh` покажет; демо идёт в запасном режиме, говорим об этом прямо.

## 6. Что говорить про ИИ (один раз, честно)

Категорию, приоритет и «Коротко» даёт ИИ, без ключа — словарь и матрица. Разбор совещания — ИИ по строгой схеме; имена
сопоставляются нечётко и при сомнении остаются пустыми. Сводка директора: факты считает сервер, ИИ только пересказывает,
каждое число проверяется. Все данные синтетические, имена вымышленные; две записи с телефона — наши.
