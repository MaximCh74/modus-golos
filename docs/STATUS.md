# Статус реализации — реализовано / имитация / план

Честная маркировка по ТЗ заказчика (п. 4.2). Обновляется после каждого этапа. Последнее обновление: замечания владельца после теста 13.11 (8 пунктов + очередь), 13.11.2026.

Название продукта — **«Модус Голос»**, подпись «Каждый голос услышан» (решение владельца 12.11.2026): шапка, заголовки страниц, PWA-манифест, плакаты QR, пункт меню Битрикс24, репозиторий `modus-golos`.

## Реализовано (работает, покрыто тестами `tests/` — 99 тестов, каждому модулю своя база)

### Этап 1 — ядро без ИИ
- **Модель данных** (`mf/db.py`): филиалы, подразделения, пользователи с иерархией `manager_id`, 18 категорий датасета с
  ответственным и SLA, обращения, отдельная связь «автор — обращение», журнал событий и журнал баллов только на добавление
  (триггеры), поддержка «У меня так же», вложения, уведомления, сессии, настройки, совещания и их пункты.
- **Демо-данные** (`mf/seed.py`): все 20 обращений A-001…A-020 из датасета с теми же номерами, типами, категориями,
  приоритетами и статусами; «дальнейшие действия» — событиями истории; A-017 отклонено с мотивировкой; A-004 и A-008
  реализованы; 3 просроченных; A-019 без ответственного (вакансия); у сотрудников есть баллы.
- **Демо-вход** «Войти как…» без паролей; права проверяются на уровне API.
- **QR-форма** `/q/<код филиала>`, **страница статуса** `/t/<токен>`, **приложение** `/app`, **панель** `/panel` — как в этапе 1.
- **Правила**: маршрутизация по категории, первый ответ, просрочка и эскалация, статусы и переходы, баллы, уведомления.
- **Безопасность**: права в API, журналы append-only, токены, ограничение частоты, CSP без inline, секреты в `.env`. Внутренний аудит
  12.11.2026 — 21 находка, исправлены все, кроме роадмапа «перед пилотом»: `docs/SECURITY.md`, тесты — `tests/test_security.py`.

### Этап 2 — режим совещания и ИИ-категория
- **STT локально** (`mf/ai/stt.py`): faster-whisper `large-v3-turbo` int8_float16 на GPU RTX 2060 (≈1,1 ГБ VRAM), прогрев при
  старте сервера, расшифровка записи с телефона/файла (webm/opus, mp4/m4a, wav, mp3, ogg), автоопределение языка (ru/kk).
  **Аудио удаляется сразу после расшифровки** — хранится только текст. Проверено: загрузка wav через API → расшифровка
  за ~1 с, файл удалён. Запасной движок — OpenAI `whisper-1` (`MF_STT=openai` или если локальная модель не поднялась и есть ключ).
- **Выбор модели STT** — `tools/stt_bench.py`, 11.11.2026, синтезированные фразы (edge-tts, ~13 с, русская и казахская;
  это дымовой тест, не замер на живой речи), полный результат — `docs/stt_bench_2026-11-11.json`:

  | модель | тип вычислений | русский (схожесть) | казахский (схожесть) | казахский без подсказки языка | время ru / kk | VRAM |
  |---|---|---|---|---|---|---|
  | medium | int8_float16 | 0,99 («Бугалтерия», «Ярлан») | 0,924 | язык kk, p=0,64 | 0,99 / 1,3 с | +1074 МБ |
  | medium | int8 | 0,99 | 0,924 | язык kk, p=0,64 | 0,84 / 1,3 с | +1073 МБ |
  | **large-v3-turbo** | **int8_float16** | **1,0** | **0,963** | **язык kk, p=0,97** | **0,53 / 0,65 с** | **+1097 МБ** |
  | large-v3-turbo | int8 | 1,0 | 0,963 | язык kk, p=0,97 | 0,57 / 0,65 с | +1096 МБ |

  Выбрана `large-v3-turbo` / `int8_float16`: лучше пишет казахский, увереннее определяет язык, быстрее, в 6 ГБ влезает с запасом.
- **Разбор совещания** (`mf/meetings.py`, `mf/ai/llm.py`): `POST /api/meetings` (аудио или текст) → обработка в фоне
  («Расшифровываем…» → «Разбираем…») → пункты: итог, решения, поручения (кто / что / срок, цитата), идеи (тип, категория,
  кто озвучил), связанные обращения (номер + что сообщить автору), открытые вопросы. Сроки из речи («до пятницы»,
  «к 15 ноября», «завтра», «через неделю», даты) → дата. **Имена сопоставляются нечётко** (`mf/ai/names.py`: основы слов,
  падежи, искажения STT «Айгерин» → Айгерим); при неуверенном совпадении исполнитель пуст + флаг «нет ответственного»,
  кандидаты подсказываются в выпадающем списке. Флаги «нет срока» / «нет ответственного» / «категория не определена» /
  «обращение не найдено».
- **Экран разбора** (`/app#/meeting`, `/panel#/meetings/<id>`): правка текста, исполнителя, срока, категории; убрать/вернуть пункт;
  добавить пункт вручную; плашка **«Демо-разбор без ИИ»**, когда разбор прошёл запасным режимом; [Отправить].
- **Отправка**: поручения → `task_status=assigned` + уведомление исполнителю; идеи → `director_decision=pending` +
  уведомление директору (SSE, прилетает без перезагрузки); связанные обращения → событие `discussed_at_meeting` с текстом
  решения + уведомление автору и всем, кто нажал «У меня так же». Проверено в браузере и тестами (петля §11 п. 7).
- **«Мои поручения»** `/app#/tasks` (все сотрудники): статусы «В работу» / «Выполнено», ведущему совещания — уведомление.
- **«На решение»** у директора — блок на главной `/app`, экран `/app#/decisions` и раздел `/panel#/decisions` (API общий):
  [Принять] → обращение `type=suggestion|problem`, `source=meeting`, автор — кто озвучил (если распознан), маршрутизация по
  категории, ответственный уведомлён; [Отклонить] — только с причиной, ведущий уведомлён.
- **Список совещаний** `/panel#/meetings`: дата, филиал, ведущий, итог одной строкой, статус, поручения выполнено/всего,
  идеи принято/на решении; ответственные видят свои, директор и администратор — все.
- **ИИ-категория обращения** (`mf/ai/__init__.py: classify_appeal`): QR-форма и приложение (если категория не выбрана) →
  один вызов LLM по схеме «Структурирование обращения» (ТЗ §7); **без ключа — словарь ключевых слов** по 18 категориям
  (`mf/ai/fallback.py`): на датасете 18/20 угадано, 2 — честно «не уверен», ошибочных нет. «Без ответственного» — только
  при вакансии категории (A-019) или когда ни ИИ, ни словарь не уверены. Результат виден в истории обращения событием
  `ai_classified` («определено ИИ» / «по ключевым словам (без ИИ)») и на экране QR-формы.
- **LLM-адаптер** (`mf/ai/llm.py`): OpenAI chat (`gpt-4o-mini`), строгий JSON (`response_format=json_object`), валидация по схеме
  с мягкой нормализацией, один повтор с текстом ошибки, затем запасной режим. Длинная расшифровка режется на куски.
  **Проверено на живом ключе 11.11.2026**: демо-планёрка §10 (поручение Ерлану «до пятницы», Айгерим без срока → флаг, идея
  про шаблон КП директору, связи с A-007 и A-012 — стабильно в двух прогонах), три посторонних текста (склад и поставки —
  три поручения с именами и сроком «до среды»; поручение без имени «кто-нибудь посмотрите» → исполнитель пуст + флаг;
  смесь русского и казахского — поручение Ерлану «до четверга», связь с A-007), категория на шести новых фразах
  (оперативность, похвала, документооборот, наставничество, прозрачность — разумно; спорные случаи ответственный правит
  на экране). По итогам поправлены промпты: решения не дублируют поручения, каждое открытое обращение проверяется на связь,
  категории даются с ответственным. Категорию идеи модель иногда оставляет пустой — тогда её подставляет словарь, директор
  может сменить при принятии.
- **Фирменный стиль заказчика** (`web/a/style.css`, 11.11.2026): дизайн-токены из CSS сайта modus-trade.kz — красный
  `#e40000` (hover `#bc262c`), тёмно-синий `#082742`, текст `#323a47`, описательный `#64748d`, рамки `#d1d5dd`, подложка
  `#eff6fd`, скругления 10/4 px; логотип с сайта (SVG, только внутри демо для заказчика); метки разделов с красной чертой;
  кнопки основная (красная) и вторичная (белая с красной обводкой); трекер статуса в стиле их таймлайна (красные круги и линия
  за пройденное, серые дальше); декор-сетка точек только на входе и в шапке QR-формы; «разработано Cyber QALQAN Systems»
  на стартовой и экране входа. **Шрифт сайта Gilroy — коммерческий, файлы не копируем; взят Montserrat (OFL, сайт тоже его
  использует), лицензия рядом со шрифтом.** Статусы обращений — отдельная приглушённая палитра, «просрочено» и «отклонено»
  с иконкой, чтобы фирменный красный читался как действие, а не тревога.

### Этап 3 — ИИ в обращениях
- **Голосовой ввод** (`POST /api/stt`, для QR-формы без входа `POST /api/public/stt` с ограничением частоты): кнопка микрофона в
  QR-форме и в форме приложения → MediaRecorder → тот же STT-адаптер, что и для совещаний (faster-whisper на GPU, запасной
  whisper-1) → текст в поле; аудио удаляется сразу. В приложении после распознавания автоматически строится черновик ИИ.
  Битый файл или выключенный STT → честная ошибка 503, не 500.
- **Черновик ИИ** (`POST /api/ai/draft`, кнопка «Черновик ИИ»): суть, предлагаемое решение, тип, категория, приоритет,
  уточняющий вопрос по схеме ТЗ §7 (`llm.classify_appeal`); поля формы подставляются, автор правит. Без ключа — словарь:
  только категория и приоритет, помечено «Черновик без ИИ».
- **Похожие обращения** (`mf/ai/similar.py`, `POST /api/ai/similar`, `POST /api/public/similar`): при отправке — блок
  «Похоже, об этом уже сообщали» с [У меня так же] / [Всё равно отправить]; в QR-форме максимум два, без авторов. С ключом —
  эмбеддинги OpenAI `text-embedding-3-small` (кэш векторов в `appeal_embeddings`, косинус, порог 0,45: «вбивать в две системы»
  → A-007 0,51; «новичкам не хватает практики с оборудованием» → A-016 0,66; «кофемашина сломалась» → ничего). Без ключа —
  совпадение основ слов + общая категория по словарю, порог 0,22, помечено «по ключевым словам». Пороги — в настройках
  (`similar_threshold`, `cluster_threshold`).
- **«Повторяющиеся темы»** (`GET /api/panel/clusters`, сводка панели): кластеры открытых обращений по полной связи (группа
  сливается, только если каждая пара не ниже порога — без цепочек), порог 0,50 для эмбеддингов; `appeals.cluster_id`
  проставляется для карты (этап 4). На seed с живым ключом: A-007 + новое «две системы», A-010/A-011/A-015 (задачи и сроки),
  A-003/A-013 (спецификации), A-002/A-014. Датасет намеренно разнородный, поэтому крупных повторов в нём нет — повторы
  появляются из новых обращений.

### ТЗ v2 — правки по кастдеву (первое интервью, один респондент)
- **Отдел развития и путь предложения к директору**: подразделение и демо-руководитель отдела развития; новые предложения
  уходят ему (или ответственному за предложения в категории, если задан), руководителю автора — уведомление-копия
  «ваш сотрудник подал предложение»; в карточке предложения кнопка «Нужно решение директора» с полем «Что требуется»;
  предложение попадает в общую очередь «На решение» вместе с идеями совещаний с пометкой источника; у каждого пункта
  «ждёт решения N дней», порог подсветки 7 дней (`settings.director_wait_days`), у директора на главной счётчик «ждут дольше
  порога». 20 обращений датасета сохраняют своих ответственных — правило для новых. Идея, принятая директором с совещания,
  идёт сразу исполнителю по категории.
- **Реальные города**: Омск (головной), Самара, Тюмень, Астана (офис), Павлодар (производство) и «Объект» для командированных:
  QR `/q/FIELD` с необязательным полем «Город / объект» (без геолокации), поле `site_city` для слоя «Объекты» на карте (этап 4).
  Seed-обращения распределены по новым городам через авторов.
- **Входы**: сотрудникам — QR и Битрикс24, приложение — инструмент руководителей (CONCEPT.md). **Битрикс24 проверен по
  официальной справке, не обещан**: `docs/BITRIX24.md` — на каком тарифе что возможно, шаги установки локального приложения,
  скоупы и REST-методы. Код интеграции в MVP не входит (план).
- **Совещания**: загрузка записи видеозвонка (mp4, mov, mkv, webm — берётся звуковая дорожка, файл удаляется); контроль
  поручений: напоминание исполнителю за день до срока, после срока — «Просрочено» + уведомление ведущему и исполнителю
  (фоновая проверка раз в минуту), строка «Поручения с совещаний: просрочено N» у директора, фильтр «только с просроченными
  поручениями» в списке совещаний.
- **Категории**: добавлена «1С и автоматизация» (ответственный — демо-пользователь «ответственный за 1С»); «Каталог и данные»
  → «Номенклатура и спецификации» — **категория уточнена по кастдеву**, A-003 остаётся в ней; словарь ключевых слов дополнен.
  8 синтетических обращений A-021…A-028 **по мотивам кастдева** (номенклатура и 1С из Омска, Павлодара, Астаны, Тюмени,
  Самары и с объекта в Атырау; два предложения, ждущие решения директора 9 и 12 дней).
- **Анонимность** — опция, выключена по умолчанию. **Мотивация**: страница `/rules` «Как начисляются баллы» без входа,
  «Премия за внедрённую идею» — первая в витрине.

### Этап 4 — главная директора и дополнения
- **Карта** (`/panel#/summary`, `web/a/mapview.js`): контуры стран из Natural Earth 50m (public domain) в `web/a/img/map.svg` —
  без внешних тайлов и ключей; 5 городов с открытыми/просроченными и главной темой, слой «Объекты» по городам из QR «Объект»
  (координаты по справочнику городов КЗ/РФ в `mf/director.py`); клик — очередь филиала; новое обращение — маркер мигает (SSE).
- **Лига филиалов** (`/panel#/league`, `/app#/league`): балл = 0,5·доля реализованного + 0,3·доля рассмотренных + 0,2·скорость
  первого ответа (веса в настройках), «Объект» вне лиги, филиалы с одним обращением помечены «мало данных»; топ сотрудников.
- **Награды** (`/app#/rewards`): витрина, заявка при достаточном балансе, одобрение/отказ администратором или директором,
  списание — отрицательной записью в журнале баллов (журнал остаётся только на добавление).
- **Настройки** (`/panel#/admin`): категории ↔ ответственный ↔ ответственный за предложения ↔ SLA, пороги «ждёт решения» и
  «без новостей», баллы, веса лиги, пороги похожести; заявки на награды; аватарки (убрать неуместную).
- **Оценка автора** (`appeals.author_urgency/author_scope`): чипы в QR-форме и приложении; итоговый `priority` отдельно —
  ИИ по ответу, тексту и числу «у меня так же», без ключа матрица (`appeals.MATRIX`); каждые 3 поддержки — на ступень выше
  (не выше высокого, не после ручной правки); в карточке оба значения, событие при смене; очередь — сортировка по приоритету и
  фильтр «Мешает работать сейчас»; у директора строка со счётчиком. 20 обращений датасета сохраняют приоритеты, у части seed —
  синтетические ответы автора.
- **ИИ-сводка директора** (`mf/director.py`, `/api/panel/director-summary`): факты за 7 дней считает сервер (новые/решённые,
  открытые и «мешают сейчас», ждут решения и самое долгое ожидание, просроченные поручения, без новостей, главная тема с
  городами); LLM получает JSON и только пересказывает; **каждое число в ответе должно быть среди фактов, иначе показывается
  шаблон**; приветствие по имени и времени суток; предложения ведут в разделы; кэш час или до новых событий, кнопка «Обновить»;
  «Озвучить» через `speechSynthesis`, если в браузере есть русский голос.
- **«Коротко»** (`appeals.brief`): создаётся вместе с категорией одним вызовом ИИ (суть / что предлагает / чего ждёт /
  «суть неясна» + вопрос); блок сверху карточки в панели и приложении, полный текст под «Показать полностью» (слова автора не
  заменяются); «Запросить уточнение: вопрос ИИ» в одно нажатие; «Пересказать заново» учитывает ответы на уточнения;
  первая строка — в очереди, уведомлениях ответственному и «Что изменили». Голос ограничен 3 минутами с подсказкой на 2:30;
  в QR-форме после расшифровки «Мы поняли так: …». Без ключа — первые два предложения с пометкой «автопересказ недоступен».
- **По словам собственника**: стадии для автора (`appeals.stage_for`) в QR-статусе и приложении — внутренние статусы не
  меняются, «Принятие решения» отмечается пройденной автоматически, если обращение пошло в работу без директора;
  «Сообщить о ходе» (событие `progress`, уведомление автору, статус не меняется), колонка «Новость автору: N дн назад»,
  напоминание ответственному «Автор ждёт новостей» при «В работе» без новостей дольше порога, строка у директора;

- **Компактный режим во фрейме Битрикса** проверен только эмуляцией (`?compact=1`, 1100 px) — на живом портале смотрит владелец; «Напомнить автору»
  в карточке повторно отправляет последний вопрос уточнения тем же механизмом (отдельного API напоминания нет). Устойчивый вход во фрейме
  (sessionStorage) проверен тестом в Firefox без сторонних cookie и сервером; на живом портале в Firefox, Safari и мобильном Битрикс24 — владелец.
- **«Отправить в WhatsApp»** — ссылка wa.me с готовым текстом: открывает WhatsApp на устройстве администратора, отправка — вручную.
- **Приглашения сотрудников без Битрикса — упрощения демо**: токен приглашения хранится в базе открытым текстом (администратору нужно
  показывать QR и ссылку повторно; перед пилотом — хранить хэш и показывать ссылку один раз); страница `/i/<token>` требует одного
  нажатия «Войти», а не входит сама при открытии — иначе ссылку «сжигал» бы предпросмотр в мессенджере; карточки PDF и Excel-импорт
  (первый лист) требуют reportlab, Pillow, fontTools, openpyxl из `requirements.txt`.
- **«Директор в кармане» без ключа** — вопросы разбираются по ключевым словам, ответы и приветствие — шаблон на тех же фактах сервера (помечено
  значком «без ИИ»); озвучка — голос браузера, если есть русский. Приветствие ИИ пересчитывается при изменении данных (первая загрузка —
  несколько секунд с живым ключом).
- **Android-приложения** — обёртки TWA над сайтом: без интернета не работают (как PWA), push-уведомлений нет; подписаны демо-ключом владельца,
  в Google Play не публиковались (`versionName` в сборке пустой — поправить при публикации).
- **Команды директора без ключа** — разбор по ключевым словам (пять команд, город по основе слова, сотрудник по нечёткому имени,
  срок по тем же правилам, что у совещаний); с ключом — LLM по строгой схеме. В обоих случаях получателей и текст считает сервер.

- **Разбор совещания без ключа OpenAI** — `mf/ai/fallback.py`: демо-планёрка из ТЗ §10 узнаётся по ключевым словам и
  отдаёт заскриптованный разбор (плашка «Демо-разбор без ИИ» на экране разбора и в списке); любая другая расшифровка —
  грубая эвристика («решили…», номера A-NNN, слово «идея»; поручений нет) с плашкой «Разбор без ИИ (эвристика)».
  **Основной режим демо — настоящий разбор с ключом** (проверен, см. выше); запасной остаётся на случай отказа сети или лимита.
- **Категория без ключа** — словарь ключевых слов (см. выше), помечается «по ключевым словам (без ИИ)».
- **Запись с телефона через MediaRecorder** — код есть (webm/opus, m4a на iOS), на localhost работает в браузере с
  микрофоном; **с телефона по HTTPS не проверено**: туннель с постоянным поддоменом ждёт `cloudflared tunnel login`
  владельца домена (см. README «Туннель»). cloudflared 2026.10.7 установлен в `~/.local/bin`, sha256 сверен.
- **Облачный STT (OpenAI whisper-1)** — код есть, на живом ключе отдельно не гонялся (локальный faster-whisper работает).
- Похожие обращения и кластеры без ключа — по ключевым словам (грубо, но честно помечено); с ключом — по смыслу.
- Голосовой ввод в браузере проверен кодом и обработкой отказа микрофона; запись с реального телефона — после туннеля.
- Карта схематичная (контуры стран без улиц и тайлов) — для демо и пилота достаточно; координаты городов объектов — по
  справочнику, незнакомый город попадает в список без маркера.
- Лига на демо-данных показательна условно: у Тюмени и Самары мало обращений, помечено «мало данных».
- Интеграция с Битрикс24 — см. выше: код есть, живой портал ждёт владельца.
- Филиалы, координаты, пользователи, награды и значения баллов — демонстрационные (`mf/seed.py`). Вход — демо без паролей.
- Один процесс, SSE-подписчики в памяти; обработка совещания — фоновая задача того же процесса.

## План

- **Хвосты**: уточняющий вопрос автору прямо в форме до отправки; web-push не делаем (in-app достаточно).
- **Аудит безопасности**: часть 1 (внутренняя) — сделана 12.11, исправления по «да» владельца — `docs/SECURITY.md`; часть 2 (внешняя) —
  владелец. «Always Use HTTPS» в Cloudflare — владелец. Выбор варианта главной кнопки (1/2/3) — владелец; в работе вариант 2.
- **Битрикс24 на живом портале**: поручения → задачи вживую, вход снаружи кнопкой, скрины из портала (пункт меню, панель во фрейме, уведомление в чате) — владелец.
- **Перед пилотом** (роадмап, `docs/SECURITY.md`): `MF_DEMO_LOGIN=0`; анонимность в самой базе (HMAC вместо ID автора); сессии — без
  токена в адресе, со сроком и хэшем; меньше данных без входа; Python ≥ 3.11 и Pillow ≥ 13 на сервере; согласия и сроки хранения ПДн.
- **Этап 5 — упаковка**: PWA (манифест, офлайн-оболочка), печатные QR с постоянного адреса, CONCEPT.md, прогон демо §11.
- Вне MVP (roadmap): калькулятор экономического эффекта, реальная выдача наград, нативное приложение, Telegram, клиентская
  обратная связь и NPS, обратная синхронизация задач Битрикс24, 1С.
