# Статус реализации — реализовано / имитация / план

Честная маркировка по ТЗ заказчика (п. 4.2). Обновляется после каждого этапа. Последнее обновление: этап 1, 11.11.2026.

## Реализовано (работает, покрыто тестами `tests/test_core.py`)

- **Модель данных** (`mf/db.py`): филиалы, подразделения, пользователи с иерархией `manager_id`, 18 категорий датасета с
  ответственным и SLA, обращения, отдельная связь «автор — обращение», журнал событий и журнал баллов только на добавление
  (триггеры), поддержка «У меня так же», вложения, уведомления, сессии, настройки; таблицы совещаний и наград заведены.
- **Демо-данные** (`mf/seed.py`): все 20 обращений A-001…A-020 из датасета с теми же номерами, типами, категориями,
  приоритетами и статусами; «дальнейшие действия» — событиями истории; A-017 отклонено с мотивировкой; A-004 и A-008
  реализованы (попадают в «Что изменили», авторам начислены баллы); 3 просроченных (A-001, A-007, A-011); A-019 без
  ответственного (вакансия «Администратор документов»); даты размазаны по 25 дням; у сотрудников есть баллы.
- **Демо-вход** «Войти как…» без паролей; права проверяются на уровне API (401/403 в тестах).
- **QR-форма** `/q/<код филиала>`: один экран — «Проблема / Идея», текст, файл, «Отправить»; без входа обращение анонимное
  с трекинг-ссылкой; если в браузере есть вход — привязывается к пользователю. Ограничение частоты с одного IP.
- **Страница статуса** `/t/<токен>`: трекер, кто отвечает, итог или причина отказа, история, ответ на уточнение. Автор не раскрывается.
- **Приложение** `/app`: главная (две большие кнопки + «Спасибо», баллы, мои обращения), новое обращение (тип, текст,
  решение, категория, приоритет, анонимно, вложение), карточка с трекером и историей, «У меня так же», ответ на уточнение,
  лента «Что изменили», уведомления (real-time по SSE), история баллов.
- **Панель** `/panel`: очередь с колонками по ТЗ и фильтрами (филиал, подразделение, категория, статус, ответственный, срок,
  поиск, «только просроченные», «без ответственного», «только открытые»); карточка справа: назначить, статус по допустимым
  переходам, уточнение, комментарий, решение или отказ с обязательной мотивировкой, история; сводка: четыре цифры
  директора, просрочено, без ответственного, по типам, по статусам, по филиалам, открытые по категориям.
- **Правила**: маршрутизация по категории → «Без ответственного» в очередь администратора; первый ответ фиксируется;
  просрочка по SLA → метка, событие `escalated`, уведомление руководителю ответственного (фоновая проверка раз в минуту и
  кнопка «Проверить просрочки сейчас»); статусы и переходы как в датасете; положительный отзыв → «Закрыто»;
  баллы +10 / +50 / +2 до +20, не за отправку, отклонённые, отзывы и анонимные; уведомления автору, ответственному, директору.
- **Безопасность**: права в API, журналы append-only, длинные случайные токены, ограничение частоты QR-формы, вложения только
  после проверки прав, CSP без inline, секреты в `.env`, только синтетические данные.

## Имитация / упрощения (видно в интерфейсе, помечено)

- Категория и приоритет в QR-форме **не определяются ИИ** (этап 3) — обращение попадает администратору «Без ответственного».
  В приложении категорию выбирает сотрудник вручную.
- Кнопка микрофона отключена (голосовой ввод — этап 3). Блок «Похоже, об этом уже сообщали» — заглушка (этап 3).
- Разделы «Награды», «Лига», «Мои поручения», «Совещание», «Совещания» в панели, «Администрирование» — заглушки с пометкой этапа.
- Филиалы, координаты, пользователи, награды и значения баллов — демонстрационные, заданы в `mf/seed.py`.
- Вход — демо без паролей; в пилоте — Битрикс24 или корпоративная учётка.
- Один процесс, SSE-подписчики в памяти (для демо и пилота достаточно).

## План

- **Этап 2 — режим совещания**: STT (faster-whisper на GPU, запасной — облачный адаптер) + LLM-разбор; загрузка аудио →
  разбор → подтверждение → отправка; связь с обращениями и уведомление автору; «На решение» у директора; «Мои поручения»;
  колонка «Совещания».
- **Этап 3 — ИИ в обращениях**: голосовой ввод, черновик, категория в фоне для QR, похожие обращения и кластеры.
- **Этап 4 — главная директора, карта, мотивация**: карта филиалов, баллы и витрина наград, лига, настройки, QR по филиалам.
- **Этап 5 — упаковка**: PWA, доступ с телефона жюри, печатные QR, CONCEPT.md.
- Вне MVP (roadmap): калькулятор экономического эффекта, реальная выдача наград, нативное приложение, Telegram, клиентская
  обратная связь и NPS, реальные интеграции с Битрикс24 и 1С.
