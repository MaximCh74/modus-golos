# Безопасность «Модус Голос»

Внутренний аудит — 12.11.2026, отдельная сессия, не писавшая код (ТЗ `docs/tz/11_security_audit.md`, часть 1). Исправления — в тот же
вечер, после «да» владельца, коммитами «Аудит 12.11, пункт …». Каждая находка закрыта тестом в `tests/test_security.py`: тест
воспроизводит атаку и проверяет, что она отклоняется. Внешний аудит (часть 2) проводит владелец.

## Что проверено и работает

- **Права на сервере.** Перебор всех маршрутов `/api`: без входа — 401 на каждом закрытом; сотрудник — 403 на панели, администрировании,
  командах директора, совещаниях и `/boss`; ответственный — 403 на администрировании и директорских маршрутах; `/boss` — только директору.
  Ответственный видит и ведёт только свою зону. Отключённый сотрудник теряет доступ сразу — и по cookie, и по токену во фрейме.
- **Анонимность.** Обращение по QR без входа ни с кем не связано в базе; автора нет в карточке, истории, трекинг-странице, ленте
  «Что изменили», «похожих», баллах и профиле; в промпты ИИ имя не уходит.
- **Вывод на страницы.** Весь текст — через `textContent`; `innerHTML`, `eval` и inline-скриптов нет; CSP `script-src 'self'` без
  `unsafe-inline`. PDF рисуется без разметки.
- **SQL.** Все значения — параметрами; в тексте запросов только имена колонок из кода.
- **ИИ.** Намерения команд и вопросы директора — белые списки; получателей считает сервер; ничего не уходит без «Отправить»; разбор
  совещания — только «на проверке»; категория — только из списка; ключа нет во фронте и в истории git.
- **Инфраструктура.** Туннель публикует только `modus.cq-systems.kz → localhost:8070`; сервер слушает 127.0.0.1; служебные пути
  (`.env`, `.git`, `/docs`, база, OpenAPI) снаружи — 404; встраивание во фрейм — только порталу из `.env`.

## Перед пилотом (роадмап)

- **F-09 — анонимность в самой базе.** Анонимное обращение из приложения связано с автором в `appeal_authors`, а уведомления автору
  хранят номер обращения. Администратор с доступом к файлу базы или резервная копия могут раскрыть автора. Сделать: вместо `user_id`
  хранить HMAC от него с секретом сервера («Мои обращения» ищутся по тому же HMAC); уведомления автору анонимного — без номера.
  В демо-данных анонимных обращений из приложения нет.
- **F-10 — сессии.** Токен сессии принимается в адресе `?s=` на любом маршруте (нужен во фрейме Битрикса и для SSE) и попадает в журнал
  uvicorn; срока на сервере нет; в базе — открытым текстом. Сделать: `?s=` — только на `/bitrix/app` и потоке событий (лучше —
  одноразовый билет), журнал без параметра `s`, срок сессии на сервере (30 дней, по приглашению — 365), в базе — хэш.
- **F-14 — что видно без входа.** Список сотрудников с должностями (`/api/auth/users` — для демо-входа; `/api/public/staff` — адресат
  «спасибо») и тексты открытых обращений в «похожих». В пилоте: список — только с демо-входом (выключен), адресат без входа — только
  отделы, «похожие» без входа — номер и категория без текста.
- **F-22 — почта в истории git.** 39 коммитов подписаны личной почтой владельца; новые — `info@cq-systems.kz`. Переписать историю —
  решение владельца (это force-push).
- **Демо-вход** — `MF_DEMO_LOGIN=0`; вход через Битрикс24 или личное приглашение.
- **Python ≥ 3.11 и Pillow ≥ 13** на сервере пилота (в Docker-образе уже так).
- **Внешний аудит** по чек-листу части 2 ТЗ.

## Персональные данные — для пилота

**Что хранится.** Всё — на сервере, где запущено приложение (сейчас — ноутбук владельца, папка `var/`); наружу — через туннель Cloudflare.

| Данные | Где | Предлагаемый срок |
|---|---|---|
| ФИО, должность, отдел, филиал, телефон, почта, ID Битрикса | `users` | пока работает + 30 дней после увольнения, затем обезличить |
| Фото профиля | `var/avatars` | пока работает |
| Тексты обращений, ответы, комментарии, вложения (фото — без EXIF) | `appeals`, `appeal_events`, `var/uploads` | 3 года, затем обезличить |
| Голос обращений и совещаний | `var/audio` | удаляется сразу после расшифровки (и при старте сервера) |
| Расшифровки совещаний | `meetings.transcript` | 12 месяцев |
| Уведомления | `notifications` | 90 дней |
| Сессии и приглашения | `sessions`, `invites` (приглашения — хэш) | 30 дней / 365 по приглашению |
| Озвучки сводок | `var/tts` | 7 дней |
| Журнал сервера | вывод uvicorn | 14 дней |

**Кому уходят данные.** OpenAI (США): тексты обращений, расшифровки, при разборе совещания — список сотрудников с должностями, команды
и вопросы директора. Битрикс24: тексты уведомлений и поручения. Cloudflare: транзит трафика.

**Записать и согласовать с юристом заказчика** (это перечень вопросов, не юридическое заключение):
1. **Согласие сотрудников** на обработку обращений, голоса и фото; отдельно — на передачу текстов в OpenAI.
2. **Уведомление о записи совещаний** — вслух в начале записи и строкой на экране «идёт запись»; расшифровку видят ведущий и директор.
3. **Сроки хранения** — по таблице выше, с автоматической очисткой.
4. **Где физически лежат данные.** Закон РК «О персональных данных и их защите» требует хранить базы с персональными данными граждан
   РК на территории РК; для филиалов в России действует аналогичное требование 152-ФЗ. Передача в OpenAI — трансграничная. Для пилота:
   сервер заказчика в РК, правовое основание для OpenAI или локальная модель и обезличивание имён перед отправкой.

```bash
python3 -m pytest -q tests/test_security.py   # атаки из аудита отклоняются
tools/preflight.sh                              # сервер, туннель, ключ, STT, база в демо-состоянии
```

Уточнение F-03 (13.11, «Быстро войти как» в меню пользователя): лимит частоты демо-входа считается для новых входов; переключение с уже открытой демо-сессии в лимит не идёт — старая сессия удаляется, новая её заменяет, сессии не копятся (`/api/auth/login-as`, тест `tests/test_stage23_user_menu.py`).
